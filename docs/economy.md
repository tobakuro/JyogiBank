# 経済設計（インフレ対策・シンク）

> 配置場所：`docs/economy.md`

---

## 1. 通貨の流れ

```
【供給】通貨が増える
  デイリーボーナス      ← 毎日一定額を全員に配布
  送金受取             ← ユーザー間移動（総量は変わらない）
  ギャンブル勝利        ← 総量は変わらない
  定期預金利息          ← 利息分だけ増加

【シンク】通貨が消える
  ギャンブルの胴元取り分 ← 期待値を95%に設定（5%が消滅）
  送金手数料            ← 送金額の1%が消滅

【変動なし】
  借金・返済            ← 総量は変わらない（利息は貸した側が受取）
  株売買               ← ユーザー間移動（総量は変わらない）
```

---

## 2. シンクの設計

### ギャンブルの胴元取り分

- 期待値を **95%** に設定する（5%が消滅）
- 例：100 JC を賭けて勝った場合、195 JC ではなく **190 JC** が戻る
- 胴元取り分は誰の残高にも加算されず消滅する
- `gambleService.ts` 内で勝敗判定と同時に処理する

```ts
// services/gambleService.ts のイメージ
const HOUSE_EDGE = 0.05; // 5%
const WIN_MULTIPLIER = 2 * (1 - HOUSE_EDGE); // 1.9倍

// 勝利時：賭け金 × 1.9 を加算（賭け金は既に引かれている）
// 敗北時：賭け金はそのまま消滅
```

### 送金手数料

- 送金額の **1%** を徴収して消滅（端数は切り捨て・最低1 JC）
- 送金者が負担する（受取人は送金額そのままを受け取る）
- 例：1,000 JC を送金 → 送金者から 1,010 JC 引かれ、受取人に 1,000 JC 届く
- 手数料が払えない場合は `INSUFFICIENT_BALANCE` エラー

```ts
// services/transactionService.ts のイメージ
const FEE_RATE = 0.01;
const calcFee = (amount: number) => Math.max(1, Math.floor(amount * FEE_RATE));
const totalCost = amount + calcFee(amount);
```

## 3. 定数の管理場所

```ts
// bot/src/config.ts
export const config = {
  // ...既存の定数...
  GAMBLE_HOUSE_EDGE: 0.05,    // ギャンブルの胴元取り分（5%）
  TRANSFER_FEE_RATE: 0.01,    // 送金手数料率（1%）
  DEPOSIT_INTEREST_RATE: 0.003, // 定期預金日利（0.3%）
} as const;
```

## 4. 経済バランスの監視

長期的なインフレ・デフレを監視するために、管理者コマンドまたは web の管理者ダッシュボードで以下を確認できるようにする。

| 指標 | 内容 |
|---|---|
| 通貨総流通量 | 全ユーザーの残高合計 |
| 1日の供給量 | デイリーボーナス総配布額 + 定期預金利息総額 |
| 1日のシンク量 | ギャンブル消滅額 + 送金手数料総額 |
| 純増減 | 供給量 - シンク量 |

バランスが崩れた場合は `config.ts` の定数を調整して対応する。
